Replication Slot Cheat Sheet

Quick-reference companion to Lesson 0001. Print me.

The mental model

A replication slot is a server-side bookmark + WAL retention anchor. Postgres keeps WAL segments from the slot’s restart_lsn onward until a consumer acknowledges them. Your client-side checkpoint table is only a note about that position; the slot is what guarantees the position still exists.

Glossary

TermMeaning
LSNLog Sequence Number — 64-bit pointer into the WAL, e.g. 0/15AF761 (segment / offset).
restart_lsnOldest WAL position the slot still needs. Postgres retains WAL from here onward.
confirmed_flush_lsnNewest position the consumer has acknowledged. Decoding resumes after this point.
activeWhether a consumer is currently connected to the slot (pg_replication_slots.active).
max_slot_wal_keep_sizePG 13+ setting capping WAL a slot may retain. Exceeding it invalidates the slot instead of filling the disk. Default -1 = unlimited (dangerous).
safe_wal_sizeBytes the slot can still retain before hitting max_slot_wal_keep_size. Watch this approach zero.
publicationDefines which tables/columns/rows are streamed. Orthogonal to the slot, which defines from where.
pgoutputBuilt-in binary logical decoding plugin (PG 10+). Needs a publication. Used by trail-replay.
test_decodingBuilt-in text plugin, no publication needed. Handy for psql experiments.

SQL quick reference

-- Create / drop (drop = destructive, admin-only)
SELECT pg_create_logical_replication_slot('my_slot', 'pgoutput');
SELECT pg_drop_replication_slot('my_slot');

-- Health check: status, retained WAL, remaining headroom
SELECT slot_name, active, invalidation_reason,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS retained_wal,
       pg_size_pretty(safe_wal_size) AS safe_wal_size
FROM pg_replication_slots;

-- Peek at changes without consuming (text plugins only)
SELECT * FROM pg_logical_slot_peek_changes('my_slot', NULL, NULL);

-- postgresql.conf safety rail
max_slot_wal_keep_size = 50GB

Do / Don’t

Do

  • Create once, idempotently; re-attach on restart
  • Keep the slot across process restarts — it holds your position
  • Set max_slot_wal_keep_size; alert on retained WAL and inactive slots
  • Drop only as an explicit admin action when decommissioning

Don’t

  • Never drop in a shutdown / signal handler
  • Never drop on transient reconnects
  • Don’t trust a client-side checkpoint without the slot behind it
  • Don’t leave unlimited retention unmonitored
